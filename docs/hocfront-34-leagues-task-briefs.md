## Цель эпика

Сделать раздел **«Лиги»** продуктово цельным — без изменения уже сильной кабинетной части:

1. Публичный каталог с поиском/фильтрами (регион Москва/Россия, уровень, статус набора), единый термин в nav/заголовке/копирайте.
2. Тарифный флаг `paid/free` на кабинете лиги + mock paid gate (без реальной оплаты) — закрывает CEO TASK-07-03.
3. Демо-данные: региональное покрытие + связка с точкой расширения «клуб → лига» на будущее.
4. QA/polish: empty/error states, SRS-синхронизация spec-номеров, `hocfront-34-pr-summary.md`.

Порядок: **34A → 34B → 34C → 34D**.

## HOCFRONT-34A — Каталог: поиск, фильтры, единый копирайт

| | |
|---|---|
| **Приоритет** | P0 |
| **Владелец** | FE |
| **Зависимости** | нет |
| **Статус** | todo |

### Цель

Дать пользователю найти лигу так же удобно, как арену: список, живой поиск, фильтр вместо одного скролла из трёх карточек.

### Scope

1. Поле поиска по названию + фильтр **регион**: `Москва` | `Россия` (остальные регионы) | все — по аналогии с фильтром города в `/arenas`.
2. Фильтр **уровень** (`SkillLevel`) и **статус набора** (`recruitingStatus: open/waitlist/closed`) — быстро найти лигу, куда сейчас берут команды.
3. URL-состояние фильтров (`q`, `region`, `level`, `recruitingStatus`, `leagueId`) — по аналогии с `/events` chips и `/arenas`.
4. Единый термин: заголовок страницы, nav-label и копирайт сверяем с TZ («Лиги» в nav → синхронизировать с заголовком страницы, не плодить третий вариант).
5. Empty state («лиг по фильтру не найдено») + error state запроса.

### Out of scope

- сама структура карточки/панели профиля — не трогаем;
- кабинет партнёра.

### Acceptance

- [ ] Поиск по названию фильтрует список
- [ ] Фильтр региона Москва/Россия/все меняет выдачу
- [ ] `/leagues?leagueId=league-002&region=Москва` открывает нужную лигу с примененным фильтром
- [ ] Единый термин в nav/title/копирайте
- [ ] Тесты: фильтр региона + deep-link + empty state

## HOCFRONT-34B — Тарифный флаг кабинета лиги + paid gate (mock)

| | |
|---|---|
| **Приоритет** | P0 |
| **Владелец** | FE / PM |
| **Зависимости** | нет |
| **Статус** | todo |

### Цель

Закрыть CEO TASK-07-03: показать paid/free состояние кабинета и ограничение функций без реальной оплаты.

### Контракт (MVP, расширение `League`)

```ts
type LeagueTariff = 'free' | 'paid'

interface LeagueCabinetTariff {
  leagueId: string
  tariff: LeagueTariff
  // при free — какие вкладки/лимиты урезаны, для демо-подсказки
  limitedFeatures: Array<'schedule' | 'posts' | 'analytics'>
}
```

### Scope

1. Поле тарифа на лиге/кабинете (mock, дефолт `free` кроме seed-лиги с `paid`).
2. В `LeaguePartnerDashboard`: бейдж тарифа в шапке + on free-плане — soft-lock (блюр/баннер «Доступно на платном тарифе») на выбранных вкладках (например analytics), без реального биллинга.
3. Публичный профиль (`LeagueProfilePanel`) без изменений — paid влияет только на кабинет, не на витрину для игрока.
4. Mock CTA «Перейти на платный тариф» — открывает информационный mock-модал (аналог `MockLeaguePortalModal`), без формы оплаты/ввода реквизитов.

### Acceptance

- [ ] Free-лига видит лок на ограниченных вкладках кабинета
- [ ] Paid-лига видит полный функционал без лока
- [ ] Admin видит тариф независимо от ограничений

## Demo script (когда закроем A–D)

1. Открыть `/leagues` — поиск по названию, фильтр «Москва» / «Россия», фильтр набора команд.
2. Открыть карточку лиги вне Москвы — добавить в избранное, посмотреть таблицу/расписание.
3. Зайти persona с `partnerMembership.kind=league` (free) → `/partner/leagues/:id` — увидеть лок на платной вкладке, нажать mock-CTA апгрейда.
4. Зайти под paid-лигой → полный доступ ко всем вкладкам кабинета.
5. Подать заявку команды в лигу как игрок → увидеть заявку в кабинете партнёра на модерации.
6. Проверить RSVP на лиговую игру в radar-виджете.
